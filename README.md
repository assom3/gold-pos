# ذهب — نظام تسعير ومخزون الذهب

> الإصدار الحالي: **0.3.0**. المرجع التقني الكامل لإعادة البناء: **[docs/SYSTEM_SPECIFICATION.md](docs/SYSTEM_SPECIFICATION.md)** — ونسخة PDF جاهزة للإرسال: **[docs/SYSTEM_SPECIFICATION.pdf](docs/SYSTEM_SPECIFICATION.pdf)**.

نظام نقاط بيع عربي (RTL) لمحل ذهب: تسعير لحظي مبني على سعر الأونصة وسعر الصرف، إدارة مخزون وأطقم، شراء بالغرام، بيع وفواتير بسياسة ربح وتقريب وسعر صرف لكل فاتورة، جرد دوري، تقارير للمالك، وصلاحيات مالك/بائع.

- سعر الأونصة يُحدَّث **تلقائياً كل 10 دقائق** من **goldapi.dev** (قابل للضبط أو التعطيل)، ويمكن إدخاله يدوياً أيضاً (مع رابط التوثيق الرسمي).
- **نسخ احتياطي تلقائي** لقاعدة البيانات (مضغوط، مجدول، مع احتفاظ بعدد محدد من النسخ) يُدار من لوحة التحكم، مع نسخ يدوي فوري وتنزيل واستعادة بأمر واحد.
- **دليل استخدام داخل النظام** (قائمة «دليل الاستخدام») بالإضافة إلى الدليل الكامل في `docs/USER_MANUAL.md`.
- الأسعار المعروضة في الواجهة هي **أسعار الذهب الخام قبل المصنعية**؛ تكلفة القطعة الفعلية تختلف حسب التصنيع والمصنع وبلد المنشأ والشحن.
- كل فاتورة تختار سياسة الربح (نسبة/ثابت/يدوي)، والتقريب (بدون/5/10)، و**طريقة الدفع** (نقدي أو **صك مصدق**)؛ والاختيار يحدّد سعر الصرف المحفوظ مع الفاتورة. الإعدادات تحفظ الافتراضيات فقط.
- الشراء يُسجَّل بسعر الغرام بعملة الشراء (USD أو LYD)، ويُحفظ سعر الصرف وتكلفة الدينار مع القطعة.
- الربح الثابت يُحسب **لكل غرام** أو **لكل قطعة** (`fixedBasis`)؛ الافتراضي لكل قطعة، والطقم يُعدّ بمكوّناته ذات الوزن.
- شاشة البيع تعرض التكلفة والربح/الخسارة للمالك، وللبائع فقط إن فعّل المالك `showCostToSeller`.

- **الواجهة:** React 19 + Vite + Tailwind 4 (تصميم فاتح/داكن، RTL كامل، ملاحظات تقنية مطوية أو مخفية على الجوال لتقليل الفوضى)
- **الخادم:** Express 5 + Prisma 6 + MySQL 8.4
- **محرك التسعير:** حزمة TypeScript مستقلة (`@gold/pricing`) بحساب عشري دقيق واختبارات
- **قاعدة البيانات:** MySQL محمول داخل المشروع، بدون خدمة نظام أو صلاحيات مدير

## التشغيل لأول مرة

```powershell
cd C:\Users\D047\Gold

# 1) تهيئة MySQL المحمول وتشغيله (مرة واحدة)
powershell -ExecutionPolicy Bypass -File .\tools\mysql-init.ps1

# 3) إعداد البيئة
copy apps\api\.env.example apps\api\.env

# 5) البيانات الأولية (إعدادات، قوائم، مستخدمان)
npm.cmd run db:seed

# 6) تشغيل الخادم والواجهة معاً
npm.cmd run dev
```

- الخادم: <http://localhost:4000> — فحص الصحة: `/api/health`

### سعر الأونصة التلقائي (goldapi.dev)

في `apps/api/.env`:

```env
GOLD_PRICE_PROVIDER=api
GOLD_PRICE_API_URL=https://goldapi.dev/api/v1
GOLD_PRICE_API_KEY=ضع-مفتاحك-هنا
# فاصل التحديث التلقائي بالدقائق (0 = تعطيل التحديث التلقائي)
GOLD_PRICE_REFRESH_MINUTES=10
```

- التوثيق الرسمي: <https://goldapi.dev/docs>
- **التحديث التلقائي:** الخادم يجلب سعر الأونصة كل `GOLD_PRICE_REFRESH_MINUTES` دقيقة (افتراضياً 10) ويحفظه كمصدر `API`، وتُحدَّث صفحة الأسعار تلقائياً بنفس الفاصل. عند الإقلاع لا يُكرَّر الجلب إذا كان آخر تحديث ما زال داخل الفاصل.
- **حد المزوّد:** الخطة المجانية في goldapi.dev = **100 طلب/ساعة**. التحديث كل 10 دقائق = 6 طلبات/ساعة فقط، أي أقل بكثير من الحد. لا تنزّل الفاصل تحت 5 دقائق إلا بعد ترقية الخطة.
- بعد التشغيل، صفحة **أسعار الذهب** تُظهر زر **جلب من goldapi.dev**، شارة «تحديث تلقائي كل 10 دقيقة»، ورابط التوثيق، وحالة تهيئة المزوّد.
- عند تعطيل المفتاح أو فشل الاتصال يبقى الإدخال اليدوي متاحاً، وتظهر رسالة عربية واضحة بدل تعطّل الصفحة.
- كل عملية جلب — يدوية أو تلقائية — تُحفظ كصف جديد في سجل الأسعار بمصدر `API` واسم المستخدم والوقت، وتُسجَّل في سجل التدقيق (`AUTO_FETCH_PRICE` للتلقائي). الجلب اليدوي يخضع لحد معدل (20 عملية/5 دقائق لكل مستخدم).

## معادلة التسعير

### البيع (لكل فاتورة)

```
قيمة الأونصة محلياً = سعر الأونصة بالدولار × سعر صرف طريقة الدفع (نقدي أو صك مصدق)
سعر غرام 24        = قيمة الأونصة محلياً ÷ 31.1035
سعر غرام العيار K  = سعر غرام 24 × (K ÷ 24)

قيمة الذهب   = وزن أساس الاحتساب × سعر غرام العيار
المجموع      = قيمة الذهب + سعر الحجر (إن وُجد)
السعر النهائي = المجموع + الربح (نسبة/ثابت/يدوي) ثم التقريب النهائي
```

### الشراء (لكل قطعة)

```
إجمالي القطعة بعملة الشراء = سعر الغرام × وزن الذهب الصافي
التكلفة بالدينار            = الإجمالي × سعر الصرف المحفوظ وقت الشراء
```

- **سياسة كل فاتورة:** طريقة الربح، قيمته، خطوة التقريب، و**طريقة الدفع** (نقدي/صك مصدق) تُختار في شاشة البيع وتُحفظ على الفاتورة نفسها مع سعر صرفها. طريقة الدفع في الإيصال هي نفسها المختارة في السياسة، وليست قيمة ثابتة. الإعدادات تحفظ **الافتراضيات** فقط، ولا تتغيّر عند بيع مختلف.
- **الربح الثابت (`fixedBasis`):** `GRAM` ⇒ `profitValue × basisWeight`، و`PIECE` ⇒ `profitValue × max(1, floor(pieceCount || 1))`؛ الافتراضي `PIECE`. الطقم يمرّر عدد مكوّناته ذات الوزن الأكبر من صفر، والتقريب يُطبَّق بعد الضرب.
- **سعر الصرف للصك المصدق مستقل** عن صرف النقدي، ويُحفظ مع الفاتورة كما استُعمل لحظة البيع.
- **الشراء بالغرام:** يُدخل سعر الغرام بعملة الشراء (USD أو LYD)، ويُحسب إجمالي القطعة ثم تكلفته بالدينار بسعر الصرف المحفوظ. لا يُعرض أي «سعر بيع تقديري» في شاشة الشراء إطلاقاً؛ سعر البيع يُحدَّد عند البيع من سعر السوق وسياسة الفاتورة.
- سعر الغرام لكل عيار يُعرض مستقلاً في صفحتي **أسعار الذهب** وبطاقة الصنف، وليس مخفياً داخل سعر القطعة.
- ثابت أونصة تروي = `31.1035` (مطابق لأمثلة الوثيقة).
- الوزن الافتراضي هو الذهب الصافي (خصم الحجر والفصوص)، ويمكن تغييره من الإعدادات.
- الحجر الذي له سعر خاص يُخصم وزنه دائماً، حتى لو كان خيار الخصم مغلقاً (BR-10).
- التقريب يُطبَّق مرة واحدة على السعر النهائي، بخطوة 0 أو 5 أو 10.

## الأصناف: التصنيف والمصنّع والمورّد

- **الطقم:** عند اختيار النوع «طقم» يُحدَّد تصنيف **«طقم»** تلقائياً ويُعطَّل حقل التصنيف. الخادم يفرض التصنيف نفسه حتى لو أرسل العميل تصنيفاً آخر.
- **المصنّع:** قائمة مرجعية تدار من **الإعدادات → المصانع**، ويُختار منها عند إضافة القطعة. تُحفظ العلاقة `manufacturerId` ويُبقى النص في عمود `manufacturer` للتوافق مع البيانات والتقارير القديمة.
- **إضافة سريعة:** في نموذج إضافة القطعة يمكن إضافة **مورّد** أو **مصنع** جديد من نفس الحقل (زر +) دون مغادرة الشاشة. البائع مسموح له بإضافة هذين النوعين فقط، وبقية القوائم للمالك.
- **تسمية الواجهة:** المستخدم يرى «ذهب» و«قطعة ذهب» في كل الشاشات. أسماء الجداول والمسارات البرمجية بقيت كما هي دون تغيير.

## ملاحظات التشغيل والنسخ الاحتياطي

- **النسخ الاحتياطي التلقائي:** يعمل داخل الخادم؛ افتراضياً نسخة مضغوطة `backups/gold_pos-YYYYMMDD-HHMMSS.sql.gz` **كل يوم 02:00** مع الاحتفاظ بآخر 14 نسخة. يُدار كله من صفحة **النسخ الاحتياطي** (المالك): تغيير التكرار والوقت وعدد النسخ، نسخ فوري، تنزيل وحذف. بطاقة حالة في الرئيسية تنبّه إلى أي تقصير.
- **نسخة خارج الجهاز:** اضبط `BACKUP_COPY_DIR` في `apps/api/.env` (قرص خارجي أو مجلد مزامنة سحابية) لتُنسخ كل نسخة إليه تلقائياً. نسخ نفس الجهاز لا تحمي من تعطّله.
- **نسخة يدوية من سطر الأوامر:** `npm.cmd run db:backup` ينشئ `backups/gold_pos-YYYYMMDD-HHMMSS.sql` دون إدخال كلمة مرور أو إيقاف MySQL. المجلد `backups/` مستثنى من git.
- **التحديث من 0.2.x:** بعد سحب الإصدار نفّذ `npm.cmd run db:push` (يضيف جدولي النسخ الاحتياطي دون حذف بيانات) ثم `npm.cmd run db:generate` وأعد تشغيل الخادم.
- مجلد بيانات MySQL: `tools/mysql/data` — مستثنى من git. انسخه فقط عند إيقاف MySQL إذا أردت نسخة كاملة تشمل إعدادات الخادم.
- **الاستعادة** (تستبدل كل البيانات الحالية): أوقف الخادم ثم:
  ```powershell
  npm.cmd run db:restore -- backups\gold_pos-YYYYMMDD-HHMMSS.sql.gz --yes
  ```
  يُنشئ الأمر نسخة أمان `backups\pre-restore-*.sql.gz` قبل الاستعادة تلقائياً.
- غيّر `SESSION_SECRET` في الإنتاج إلى قيمة عشوائية طويلة، واضبط `APP_ORIGIN` على نطاق الواجهة.
- الأسعار تُحفظ كسجل تاريخي غير قابل للتعديل؛ كل إدخال جديد يُضاف كصف مستقل ويُسجَّل باسم المستخدم.
