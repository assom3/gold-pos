## 1. ما يفعله النظام

- يحوي **دليل استخدام داخل النظام** (القائمة الجانبية ← «دليل الاستخدام») بشرح مختصر لكل شاشة وبحث نصي، وهذا الملف هو الدليل الكامل.
- يحسب سعر الغرام لكل عيار من سعر أونصة الذهب بالدولار وسعر الصرف المحلي، ويحدّث سعر الأونصة تلقائياً من goldapi.dev. الأسعار المعروضة **للخام قبل المصنعية**؛ تكلفة القطعة تختلف حسب التصنيع والمصنع وبلد المنشأ والشحن.
- واجهة النظام مختصرة على الجوال: الملاحظات التقنية والتوضيحات الطويلة مخفية أو مطوية، والأساسيات تظهر أولاً.
- يسجّل المشتريات بسعر الغرام، ويحفظ سعر الصرف يوم الشراء وتكلفة القطعة بالدينار.
- يبيع القطع والأطقم ويصدر فواتير مرقّمة، مع **سياسة ربح وتقريب وسعر صرف مستقلة لكل فاتورة**.
- يتابع المخزون ويقيّمه بأسعار اللحظة، ويدير الجرد الدوري والفروقات.
- يقدّم تقارير مبيعات وأرباح ومخزون وأسعار وسجل تعديلات (للمالك).
- يحمي العمليات بصلاحيتين: **مالك** و**بائع**.

## 2. تشغيل النظام وإيقافه

### المتطلبات

- Windows 10/11 (أو نظام مشابه مع تعديل مسارات MySQL).
- Node.js 20 أو أحدث.
- قاعدة MySQL المحمولة الموجودة داخل مجلد المشروع.

### أول تشغيل (مرة واحدة)

افتح PowerShell داخل مجلد المشروع `C:\Users\D047\Gold` ثم:

```powershell
# 1) تهيئة قاعدة البيانات المحمولة وتشغيلها
powershell -ExecutionPolicy Bypass -File .\tools\mysql-init.ps1

# 2) تثبيت الحزم
npm.cmd install

# 3) إعداد ملف البيئة
copy apps\api\.env.example apps\api\.env
# عدّل DATABASE_URL و SESSION_SECRET، وأضف GOLD_PRICE_API_KEY إن أردت جلب الأسعار

# 4) إنشاء الجداول والبيانات الأولية
npm.cmd run db:generate
npm.cmd run db:push
npm.cmd run db:seed

# 5) تشغيل الخادم والواجهة
npm.cmd run dev
```

> على هذا الجهاز يُستعمل `npm.cmd` بدل `npm` بسبب سياسة تنفيذ PowerShell.

### التحديث من إصدار أقدم (0.2.x ← 0.3.0)

الإصدار 0.3.0 يضيف جدولين لقاعدة البيانات (النسخ الاحتياطي)، لذلك بعد سحب التحديث نفّذ مرة واحدة:

```powershell
npm.cmd install
npm.cmd run db:push
npm.cmd run db:generate
```

`db:push` **يضيف** الجداول الجديدة فقط ولا يحذف أي بيانات. ثم أعد تشغيل الخادم؛ سيُنشئ أول نسخة احتياطية تلقائياً (راجع القسم 14). إن ظهر خطأ `EPERM` أثناء `db:generate` فأوقف الخادم أولاً (Ctrl+C) ثم أعد الأمر.

### التشغيل اليومي

```powershell
# تشغيل قاعدة البيانات
powershell -ExecutionPolicy Bypass -File .\tools\mysql-start.ps1

# تشغيل الخادم والواجهة
npm.cmd run dev
```

- الواجهة: <http://localhost:5173>
- الخادم: <http://localhost:4000> — فحص الصحة: `/api/health`

### الإيقاف

```powershell
# أوقف الخادم والواجهة بـ Ctrl+C في نافذة التشغيل، ثم:
powershell -ExecutionPolicy Bypass -File .\tools\mysql-stop.ps1
```

> لا تنسخ مجلد بيانات MySQL أثناء تشغيله. أوقف MySQL أولاً.

## 4. الشاشة الرئيسية

تعرض:

- **السوق الآن:** سعر الأونصة بالدولار، سعر الصرف، وسعر غرام 21 (أو العيار الافتراضي).
- **تنبيه قدم السعر** إذا تجاوزت آخر تحديثات الأسعار المدة المسموحة (`priceStaleHours`، افتراضياً ساعتان).
- **مبيعات اليوم/الشهر، القطع المتاحة، وزن الذهب الصافي.**
- **آخر المبيعات، آخر جرد، وإجراءات سريعة** (بيع جديد، إضافة قطعة ذهب، تحديث الأسعار، تقييم المخزون).
- **بطاقة «النسخ الاحتياطي» (للمالك فقط):** حالة النسخ (سليم / يحتاج انتباه / لا توجد نسخة)، وقت آخر نسخة ناجحة وحجمها، والموعد التالي، مع زر **«نسخ احتياطي الآن»** ورابط «إدارة النسخ». تتحول الشارة إلى تحذير إذا مضى وقت طويل دون نسخة ناجحة أو فشلت آخر محاولة.

## 5. أسعار الذهب

من القائمة: **أسعار الذهب**.

> الأسعار المعروضة هنا هي **أسعار الذهب الخام قبل المصنعية**. تكلفة القطعة الفعلية تختلف حسب التصنيع والمصنع وبلد المنشأ والشحن، وتظهر عند تسعير القطعة أو بيعها.

### الإدخال اليدوي

1. أدخل **سعر أونصة الذهب بالدولار** (مثال: `2000`).
2. أدخل **سعر الصرف** (كم من العملة المحلية يساوي دولاراً واحداً).
3. يظهر جدول **سعر الغرام لكل عيار** فوراً كمعاينة.
4. اضغط **حفظ** لتثبيت السعرين في السجل.

> الحساب: قيمة الأونصة محلياً = سعر الأونصة × سعر الصرف، ثم سعر غرام 24 = قيمة الأونصة ÷ 31.1035، ثم سعر غرام العيار = سعر غرام 24 × (العيار ÷ 24).

> **الصلاحيات:** تعديل **سعر الأونصة** يدوياً أو طلب الجلب الخارجي متاح **للمالك فقط**؛ البائع يستطيع تحديث **سعر الصرف** فقط. التحديث التلقائي يعمل من الخادم بلا تدخل من أي مستخدم.

### جلب سعر الأونصة تلقائياً (goldapi.dev)

1. أضف المفتاح في `apps/api/.env`:

   ```env
   GOLD_PRICE_PROVIDER=api
   GOLD_PRICE_API_URL=https://goldapi.dev/api/v1
   GOLD_PRICE_API_KEY=ضع-مفتاحك-هنا
   GOLD_PRICE_REFRESH_MINUTES=10
   ```

2. أعد تشغيل الخادم.
3. سترى في صفحة الأسعار شارة **«تحديث تلقائي كل 10 دقيقة»**، وزر **جلب من goldapi.dev**، ورابط التوثيق <https://goldapi.dev/docs>.
4. الخادم يجلب سعر الأونصة تلقائياً كل 10 دقائق ويحفظه باسم المالك ووقت الجلب، وتتحدّث الصفحة المفتوحة بنفس الفاصل.
5. أدخل سعر الصرف يدوياً إن لم يكن محدّثاً.

ملاحظات:

- المفتاح يبقى في الخادم ولا يظهر في المتصفح.
- كل جلب — تلقائي أو يدوي — يُسجَّل في سجل الأسعار ويظهر في تقرير الأسعار وسجل التعديلات.
- **حصة goldapi.dev المجانية:** 100 طلب/ساعة. الفاصل 10 دقائق = 6 طلبات/ساعة فقط. لا تُنقص الفاصل تحت 5 دقائق دون ترقية الخطة.
- لتغيير الفاصل عدّل `GOLD_PRICE_REFRESH_MINUTES` وأعد تشغيل الخادم؛ واجعله `0` لتعطيل التحديث التلقائي (يبقى الجلب اليدوي متاحاً).
- عند رفض المفتاح أو تجاوز الحد أو انقطاع الشبكة تظهر رسالة عربية واضحة، ويبقى الإدخال اليدوي متاحاً.
- زر الجلب اليدوي محدود بـ 20 عملية كل 5 دقائق لكل مستخدم.

### سجل الأسعار

أسفل الصفحة سجل بكل تحديث: النوع (أونصة/صرف)، القيمة، المصدر (يدوي/API)، من أدخله، ومتى.

## 6. تسجيل شراء قطعة ذهب (بالغرام)

من القائمة: **الذهب** ثم زر **إضافة قطعة ذهب** (أو من إجراء سريع في الرئيسية).

### نوع الصنف

- **قطعة:** صنف مفرد.
- **طقم:** عدة مكوّنات (خاتم، سلسلة، حلق...) لكل منها عيار ووزن. عند اختيار «طقم» يُثبَّت التصنيف على **«طقم»** تلقائياً ويُعطَّل حقل التصنيف.

### الحقول الأساسية

| الحقل | ملاحظات |
|---|---|
| كود الصنف | تلقائي `P-0001`/`S-0001` أو يدوي حسب الإعدادات. في الوضع التلقائي الكود المعروض **معاينة فقط**؛ الخادم يولّد الكود النهائي عند الحفظ فلا يتكرر ولو فُتحت الشاشة أكثر من مرة |
| اسم القطعة | مطلوب |
| العيار | مطلوب (مثل 18 أو 21 أو 24) |
| التصنيف / المقاس | اختياريان — التصنيف يُثبَّت على «طقم» عند اختيار النوع طقم |
| الكمية | للقطع المتطابقة فقط؛ إذا كانت أكثر من 1 يجب تأكيد «كل القطع بنفس الوزن والمواصفات» |
| الوزن الإجمالي | مطلوب بالغرام |
| وزن الحجر / وزن الفصوص | يُخصمان حسب أساس الوزن |
| سعر الحجر | اختياري؛ إن وُجد يُخصم وزنه دائماً |
| المكوّنات | للأطقم فقط، وتُجمع أوزانها تلقائياً |

### المورّد والمصنّع

- **المورّد:** اختر من القائمة المنسدلة.
- **المصنّع / العلامة:** اختر من قائمة **المصانع** التي يديرها المالك من الإعدادات.
- لإضافة مورّد أو مصنع جديد بسرعة: اضغط زر **+** بجانب الحقل، اكتب الاسم، ثم **إضافة**. القيمة الجديدة تُحفظ وتُختار مباشرة دون مغادرة الشاشة.
- البائع يستطيع إضافة **مورّد** أو **مصنع** فقط؛ بقية القوائم (التصنيفات، العيارات…) يضيفها المالك من الإعدادات.

### بيانات الشراء من الجملة

1. أدخل **سعر الغرام** الذي اشتريت به.
2. اختر **عملة الشراء** (مثل USD أو LYD).
3. إذا كانت العملة أجنبية، أدخل **سعر الصرف يوم الشراء**.
4. يعرض النظام مباشرة:
   - إجمالي القطعة بعملة الشراء = سعر الغرام × وزن الذهب الصافي.
   - التكلفة بالدينار = الإجمالي × سعر الصرف.
   - إجمالي الكمية إذا كانت أكثر من قطعة.

> **لا يوجد «سعر بيع تقديري» في شاشة الشراء إطلاقاً.** سعر البيع يُحدَّد لحظة البيع من سعر السوق وسياسة الفاتورة، لأن الأسعار تتغيّر.

### بعد الحفظ

- تُحفظ القطعة بحالة **موجود** وتظهر في صفحة الذهب والمخزون.
- لا يمكن تعديل صنف **مباع**؛ ويُمنع حذف صنف مرتبط بفاتورة.

## 7. البيع وسياسة كل فاتورة

من القائمة: **المبيعات** ثم **بيع جديد**.

### الخطوة 1: اختيار الأصناف

1. ابحث بالكود أو الاسم في شريط البحث.
2. اضغط على القطعة لإضافتها إلى السلة (أو امسح الكود بالباركود إن وُجد).
3. عدّل **الكمية** إن كانت القطعة متعددة، أو أزل السطر.
4. يظهر **السعر المقترح** لكل سطر، ويمكنك تعديله يدوياً.

#### ما الذي يظهر من التكلفة والربح أثناء البيع

التكلفة والربح/الخسارة في شاشة البيع **تظهران للمالك دائماً**، وتظهران للبائع فقط إذا فعّل المالك في الإعدادات خيار **إظهار التكلفة للبائع** (`showCostToSeller`). إن كان الخيار مغلقاً فلا تظهر هذه الأرقام في السلة ولا في الملخص ولا في نافذة التأكيد.

| الموضع | ما يُعرض |
|---|---|
| كل سطر في السلة | **سعر الشراء** للوحدة، **تكلفة الشراء** للكمية المختارة، و**الربح/الخسارة** لهذا السطر. وللطقم يظهر أيضاً **عدد القطع في الطقم**. |
| ملخص الفاتورة | **تكلفة الشراء** الإجمالية، **إجمالي سعر البيع**، و**صافي الربح/الخسارة**. |
| نافذة التأكيد | نفس أرقام التكلفة وإجمالي البيع وصافي الربح/الخسارة قبل إصدار الفاتورة. |

طريقة عرض الربح/الخسارة:

- إن كانت تكلفة الشراء غير معروفة أو تساوي صفراً تظهر شرطة `—`.
- إن تساوى سعر البيع مع التكلفة تظهر `ربح 0`.
- إن كان سعر البيع أقل من التكلفة تظهر **خسارة** باللون الأحمر مع النسبة المئوية للخسارة من التكلفة.
- إن كان سعر البيع أعلى من التكلفة يظهر **ربح** باللون الأخضر مع النسبة المئوية للربح من التكلفة.

> هذه الأرقام **للعرض فقط**؛ السعر النهائي المحفوظ في الفاتورة يحسبه الخادم، وحقول الشراء لا تُرسل أصلاً إلى من لا يملك صلاحية رؤيتها.

### الخطوة 2: سياسة الربح والتقريب (لكل فاتورة)

هذه الاختيارات تُطبَّق على **هذه الفاتورة فقط** ولا تغيّر افتراضيات المحل:

| الاختيار | المعنى |
|---|---|
| **طريقة الربح: نسبة مئوية** | الربح = نسبة من (قيمة الذهب + الحجر) |
| **طريقة الربح: مبلغ ثابت** | يُضرب المبلغ الذي تدخله في **أساس الربح الثابت**: لكل غرام أو لكل قطعة |
| **طريقة الربح: سعر نهائي يدوي** | تكتب السعر النهائي مباشرة، والربح = اليدوي − التكلفة |
| **التقريب** | بدون / أقرب 5 / أقرب 10 — يُطبَّق مرة واحدة على السعر النهائي |

#### أساس الربح الثابت (`fixedBasis`)

يظهر حقل **«أساس الربح الثابت»** فقط عند اختيار **«مبلغ ثابت»**. الاختياران هما:

| الاختيار | المعنى | مثال بمبلغ `100` |
|---|---|---|
| **لكل غرام** (`GRAM`) | يُضرب المبلغ في وزن أساس الاحتساب المستخدم لحساب قيمة الذهب. | إذا كان وزن الأساس `9 غ` فالربح `100 × 9 = 900`. |
| **لكل قطعة** (`PIECE`) | يُضرب المبلغ في عدد القطع أو المكوّنات، بحد أدنى قطعة واحدة. | إذا كانت الكمية `3` فالربح `100 × 3 = 300`. |

- **الافتراضي «لكل قطعة»**؛ يأتي من الإعدادات ويمكن تغييره في هذه الفاتورة فقط دون تغيير افتراضيات المحل.
- **تنبيه للطقم:** عند اختيار «لكل قطعة» يُعدّ النظام المكوّنات ذات الوزن الأكبر من صفر؛ فطقم من ثلاثة مكوّنات يعني ثلاث وحدات ربح. وعند اختيار «لكل غرام» يُضرب المبلغ في مجموع أوزان أساس المكوّنات.
- يُضاف الربح بعد قيمة الذهب والحجر، ثم يُطبَّق التقريب مرة واحدة على السعر النهائي.

### الخطوة 3: طريقة الدفع وسعر الصرف

طريقة الدفع في هذه البطاقة هي **نقدي** أو **صك مصدق**، وهي التي تُسجَّل في الفاتورة وتظهر في الإيصال. لكل فاتورة صرفان:

- **صرف النقدي.**
- **صرف الصك المصدق** (مستقل تماماً عن النقدي).

1. اختر **نقدي** أو **صك مصدق**.
2. عدّل سعر الصرف المرتبط بالطريقة المختارة إن اختلف عن سعر السوق.
3. يُحفظ مع الفاتورة كلٌّ من طريقة الدفع وسعر صرفها كما استُعملا لحظة البيع.

> لا توجد طريقة دفع أخرى في شاشة البيع؛ اختيار «صك مصدق» يضبط السجل تلقائياً على «صك» ويستعمل صرفه المستقل، واختيار «نقدي» يضبطه على «نقدي». الفواتير القديمة المسجّلة بلا طريقة دفع تظهر «غير محدد».

### الخطوة 4: العميل

- اسم العميل وهاتفه: اختياريان.
- تظهر أسفل الحقلين طريقة الدفع المسجّلة من الخطوة 3 للمراجعة فقط.

### الخطوة 5: التأكيد والفاتورة

1. راجع ملخص الفاتورة (عدد الأصناف والقطع، الوزن، البائع، الإجمالي).
2. اضغط **إتمام البيع** ثم **تأكيد وإصدار الفاتورة**.
3. تُخصم الكميات من المخزون مباشرة، ويظهر رقم الفاتورة `INV-00001`.
4. يمكنك **طباعة الإيصال** أو فتح **الفاتورة كاملة**.
5. بعد البيع تُعاد سياسة الفاتورة إلى افتراضيات المحل تلقائياً للفاتورة التالية.

### مثال حسابي

قطعة وزن ذهبها الصافي `5.00 غ`، عيار `18`، سعر غرام العيار `959.58`، سياسة `نسبة 10%`، تقريب `أقرب 5`:

```
قيمة الذهب = 5.00 × 959.58 = 4,797.90
+ الربح 10% = 479.79
= 5,277.69
بعد التقريب لأقرب 5 = 5,280.00
```

## 14. النسخ الاحتياطي والاستعادة

يحمي النظام بياناتك بنسخ احتياطية **تلقائية** تُدار بالكامل من داخل النظام، مع إمكانية النسخ اليدوي والاستعادة بأمر واحد.

### 14.1 النسخ التلقائي (الافتراضي)

- يُنشئ النظام **نسخة مضغوطة** (`.sql.gz`) من قاعدة البيانات **كل يوم الساعة 02:00** بتوقيت الجهاز، ويحتفظ بآخر **14 نسخة** ويحذف الأقدم تلقائياً.
- تعمل الجدولة **ما دام الخادم شغّالاً**. إذا كان الخادم متوقفاً وقت الموعد، تُنفَّذ النسخة المتأخرة **فور تشغيله** (بعد نحو 15 ثانية).
- بعد كل نسخة يفحص النظام الملف (يفك ضغطه ويتأكد أنه كامل) قبل أن يعتبرها ناجحة.
- إذا فشلت نسخة يُعاد المحاولة بعد 30 دقيقة، وتظهر رسالة السبب في صفحة النسخ.

### 14.2 صفحة «النسخ الاحتياطي» (للمالك)

من القائمة الجانبية: **النسخ الاحتياطي**.

| العنصر | وظيفته |
|---|---|
| **نسخ احتياطي الآن** | ينشئ نسخة فورية، وتنتظر الشاشة حتى تنتهي (ثوانٍ عادة) |
| بطاقات الحالة | آخر نسخة ناجحة، النسخة التالية، عدد النسخ المحفوظة وحجمها، نظام الجدولة |
| **الجدولة التلقائية** | تفعيل/إيقاف النسخ التلقائي، **تكرار النسخ** (كل 6 ساعات، 12 ساعة، يوم، يومين، أسبوع)، **وقت النسخ اليومي**، و**عدد النسخ المحفوظة** (من 3 إلى 90) ثم «حفظ» |
| **مكان الحفظ** | المجلد المحلي للنسخ (افتراضياً `backups\` داخل المشروع)، والنسخة الإضافية إن فُعّلت |
| **سجل النسخ** | كل المحاولات (ناجحة وفاشلة) مع التاريخ والنوع (يدوية/مجدولة) والحجم؛ زر **تنزيل** وزر **حذف** لكل نسخة |

> وقت النسخ اليومي يُستعمل مع الفواصل «يوم» فأكثر. مع الفواصل القصيرة (6 أو 12 ساعة) تُحسب النسخة التالية من وقت آخر نسخة ناجحة.

**تنبيهات الحالة:** تظهر شارة «يحتاج انتباه» إذا لم تنجح أي نسخة خلال ضعف الفاصل (وبحد أدنى 36 ساعة)، أو فشلت آخر محاولة. وتظهر «لا توجد نسخة» قبل أول نسخة.

### 14.3 احفظ نسخة خارج الجهاز (مهم جداً)

النسخ داخل مجلد المشروع تحميك من الأخطاء البرمجية والحذف غير المقصود، **لكنها لا تحميك إذا تعطّل الجهاز أو سُرق**. اختر إحدى الطريقتين:

1. **تلقائي (موصى به):** في ملف `apps\api\.env` أضف سطراً بمجلد على قرص خارجي أو مجلد مزامنة سحابية (OneDrive/Google Drive…):

   ```
   BACKUP_COPY_DIR=D:\GoldBackups
   ```

   ثم أعد تشغيل الخادم. تُنسخ كل نسخة ناجحة تلقائياً إلى هذا المجلد، وتُحذف معها عند تطبيق الاحتفاظ. إذا تعذّر النسخ إليه (القرص غير متصل مثلاً) تظهر ملاحظة تحذير بجانب النسخة ولا تفشل النسخة المحلية.
2. **يدوي:** نزّل نسخة من الصفحة (زر التنزيل) واحفظها في مكان آمن أسبوعياً على الأقل.

### 14.4 إعدادات متقدمة (في `apps\api\.env`)

| المتغير | الغرض |
|---|---|
| `BACKUP_DIR` | مجلد مختلف لحفظ النسخ بدل `backups\` |
| `BACKUP_COPY_DIR` | مجلد النسخة الإضافية (انظر أعلاه) |
| `BACKUP_MYSQLDUMP_PATH` | مسار `mysqldump.exe` إن لم يُكتشف تلقائياً |
| `BACKUP_SCHEDULER=off` | تعطيل الجدولة من البيئة (النسخ اليدوي يبقى متاحاً) |

بعد أي تعديل أعد تشغيل الخادم.

### 14.5 الاستعادة من نسخة احتياطية

> ⚠ الاستعادة **تستبدل كل بيانات النظام الحالية** بمحتوى النسخة. تُنفَّذ من سطر الأوامر عمداً لتجنّب الضغط عليها بالخطأ.

1. **أوقف الخادم والواجهة** (Ctrl+C)، وأبقِ MySQL شغّالاً.
2. من مجلد المشروع شغّل (غيّر اسم الملف):

   ```powershell
   npm.cmd run db:restore -- backups\gold_pos-YYYYMMDD-HHMMSS.sql.gz --yes
   ```

   يقبل الأمر ملفات `.sql.gz` و`.sql`. بدون `--yes` يعرض التحذير فقط ولا يغيّر شيئاً.
3. قبل الاستعادة ينشئ الأمر **نسخة أمان** تلقائياً باسم `backups\pre-restore-...sql.gz`؛ إذا لم تكن النتيجة ما تريد، استعدها بنفس الأمر لترجع لما كان قبل.
4. شغّل الخادم من جديد وتحقق من البيانات.

> نسخة من جهاز آخر أو بعد فقدان الجهاز: ثبّت النظام وMySQL كما في القسم 2 ثم نفّذ نفس أمر `db:restore` على ملف النسخة.

### 14.6 النسخ من سطر الأوامر (بدون النظام)

```powershell
npm.cmd run db:backup
```

ينشئ ملفاً غير مضغوط `backups\gold_pos-YYYYMMDD-HHMMSS.sql` دون الحاجة لتشغيل الخادم. مفيد قبل التحديثات الكبيرة أو عند فشل الخادم.

### 14.7 نسخة كاملة للمجلد (احتياطي إضافي)

1. أوقف الخادم والواجهة.
2. أوقف MySQL:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\tools\mysql-stop.ps1
   ```

3. انسخ مجلد `tools\mysql\data` إلى مكان آمن بتاريخ اليوم.
4. أعد تشغيل MySQL عند الحاجة.

> `npm.cmd run db:reset` **يحذف كل البيانات** ويعيد الحالة الأولية. لا تستعمله إلا عند بداية جديدة متعمّدة.

| السعر النهائي لا يطابق الحساب | تقريب مفعّل أو ربح مختلف | راجع «طريقة الربح» و«أساس الربح الثابت» و«التقريب» في نفس الفاتورة |
| لا يظهر حقل «أساس الربح الثابت» | طريقة الربح ليست «مبلغ ثابت» | اختر «مبلغ ثابت» أولاً، ثم حدّد «لكل غرام» أو «لكل قطعة» |
| الربح الثابت في طقم مختلف عن المتوقع | «لكل قطعة» يضرب في عدد المكوّنات ذات الوزن، و«لكل غرام» يضرب في مجموع أوزان الأساس | راجع اختيار الأساس في بطاقة السياسة وعدد مكوّنات الطقم |
| لا تظهر التكلفة أو الربح في شاشة البيع | البائع غير مسموح له، أو `showCostToSeller` مغلق | فعّل الخيار من الإعدادات؛ المالك يرى هذه الأرقام دائماً |
| تظهر «خسارة» باللون الأحمر | سعر البيع أقل من تكلفة الشراء المحفوظة | راجع السعر المقترح أو عدّل سعر البيع إن كانت الخسارة غير مقصودة |
| سعر الصك مختلف عن النقدي | هذا سلوك مقصود | لكل فاتورة صرف نقدي وصرف صك مستقل |
| لا يمكن تعديل/حذف صنف | مباع أو مرتبط بفاتورة | استخدم صنفاً جديداً، أو ألغِ الفاتورة للمالك إن كان مناسباً |
| «لا يمكن تنفيذ العملية لوجود بيانات مرتبطة» | القيمة مستعملة في سجل قائم | عطّل القيمة بدل حذفها، أو احذف الارتباط أولاً |
| «كود الصنف مستخدم مسبقاً» | كود يدوي مكرر، أو معاينة قديمة في الوضع اليدوي | اترك الكود فارغاً في الوضع التلقائي، أو اختر كوداً آخر غير موجود |
| «حدث خطأ غير متوقع… رقم المرجع» | خطأ داخلي غير مصنّف | أعد المحاولة؛ إن تكرر فأبلغ المسؤول برقم المرجع `requestId` الظاهر في الرسالة |
| «قاعدة البيانات غير مهيأة» | مخطط Prisma لم يُحدَّث بعد تحديث النظام | نفّذ `npm.cmd run db:generate` ثم `npm.cmd run db:push` وأعد تشغيل الخادم |
| المخزون يظهر فارغاً أو لا يُحمّل | الخادم قديم أو قاعدة البيانات غير متزامنة | أعد تشغيل الخادم، ثم نفّذ `db:generate` و`db:push`، وحدّث الصفحة |
| شارة «يحتاج انتباه» أو «لا توجد نسخة» في النسخ الاحتياطي | لم تنجح نسخة حديثاً أو فشلت آخر محاولة | افتح صفحة النسخ الاحتياطي واقرأ سبب الفشل في السجل، ثم اضغط «نسخ احتياطي الآن» |
| «أداة mysqldump غير موجودة» | المسار غير مكتشف | اضبط `BACKUP_MYSQLDUMP_PATH` في `apps\api\.env` وأعد تشغيل الخادم |
| «الملف غير موجود» بجانب نسخة | حُذف الملف يدوياً من المجلد | احذف سجله من الصفحة، وسيُنشئ النظام نسخة جديدة |
| لا تظهر النسخ الاحتياطي في القائمة | الحساب بائع، أو الجداول الجديدة لم تُنشأ | الصفحة للمالك فقط؛ بعد التحديث نفّذ `npm.cmd run db:push` ثم أعد تشغيل الخادم |
| لم يُحفظ رقم في حقل | الحقل يقبل أرقاماً فقط | أدخل قيمة رقمية بدون رموز عملة؛ العملة تظهر بجانب الحقل |

### اختبار سريع للتشغيل

```powershell
# فحص صحة الخادم
Invoke-WebRequest http://127.0.0.1:4000/api/health
```

إن أعاد `200` فالخادم يعمل.

## 16. قواعد يجب تذكّرها

1. **الأسعار تُحسب من جديد عند البيع**، لا من سعر بيع مخزّن سابقاً.
2. **ثابت أونصة تروي = 31.1035 غرام**، وهو المعتمد في كل الحسابات.
3. **سعر الغرام يُعرض لكل عيار على حدة**، ولا يُدمج داخل سعر القطعة.
4. **سياسة الربح والتقريب لكل فاتورة**؛ الإعدادات افتراضيات فقط.
5. **صرف الصك المصدق مستقل عن صرف النقدي**، ويُحفظ مع الفاتورة.
6. **التقريب مرة واحدة** على السعر النهائي فقط، بخطوة 0 أو 5 أو 10.
7. **الشراء بالغرام** يحفظ سعر الغرام وسعر الصرف وتكلفة الدينار، ولا يعرض سعر بيع تقديري.
8. **حجر له سعر خاص** يُخصم وزنه دائماً، حتى لو كان خصم الحجر مغلقاً.
9. **إلغاء البيع يعيد الكميات** ويُبقي الفاتورة في السجل بحالة «ملغاة».
10. **آخر مالك نشط لا يُعطَّل**، وكلمات المرور لا تُسجَّل نصاً في أي مكان.
11. **سعر الأونصة يتحدّث تلقائياً كل 10 دقائق** (قابل للضبط)، وسعر الصرف يبقى يدوياً، وتعديل الأونصة للمالك فقط.
12. **الطقم تصنيفه «طقم» دائماً**، ولا يمكن اختيار تصنيف آخر له.
13. **كل رسائل الخطأ عربية** ومختصرة، والتفاصيل التقنية تبقى في سجل الخادم مع رقم مرجعي.
14. **الربح الثابت** إما «لكل غرام» أو «لكل قطعة»؛ الافتراضي «لكل قطعة»، والطقم يُحسب بمكوّناته ذات الوزن الأكبر من صفر.
15. **التكلفة والربح/الخسارة في شاشة البيع** تظهران للمالك، وللبائع فقط إذا فعّل المالك `showCostToSeller`.
16. **الأسعار الظاهرة للخام فقط قبل المصنعية**؛ لا تُفهم كسعر بيع نهائي للقطعة.
17. **نسخ احتياطي تلقائي يومي** يُدار من صفحة «النسخ الاحتياطي»؛ فعّل `BACKUP_COPY_DIR` أو انسخ ملفاً خارج الجهاز بانتظام، فنسخ نفس الجهاز لا تحمي من تعطّله.
18. **الاستعادة تستبدل كل البيانات** وتتم من سطر الأوامر بـ`npm.cmd run db:restore -- <ملف> --yes` بعد إيقاف الخادم، وتُنشئ نسخة أمان تلقائياً.
19. **صنف الجرد بكمية أكبر من 1** يُعدّ في سطر واحد: الوزن المتوقع = وزن القطعة × الكمية.
20. **رمز العملة 3 حروف لاتينية** (مثل LYD)، وهي عملة المحل المحلية التي تُحسب بها تكلفة الشراء.
