## 0.3.0 — 2026-11-18

إصدار **النسخ الاحتياطي التلقائي ودليل الاستخدام** مع إصلاحات من مراجعة شاملة للكود. **يتطلب `npm.cmd run db:push`** (جدولان جديدان، إضافة فقط) ثم `db:generate` وإعادة تشغيل الخادم.

### 1) النسخ الاحتياطي التلقائي (جديد)

- **جدولان:** `BackupSetting` (صف واحد: تفعيل، فاصل 6/12/24/48/168 ساعة، وقت يومي، عدد الاحتفاظ 3–90) و`BackupRun` (سجل كل محاولة).
- **الخدمة `lib/backup.ts`:** `mysqldump --single-transaction` ← gzip ← **تحقق سلامة** (فك الضغط والتأكد من سطر `Dump completed`) ← `gold_pos-YYYYMMDD-HHMMSS.sql.gz` ← احتفاظ بآخر N نسخة. كلمة المرور عبر `MYSQL_PWD` لا سطر الأوامر. مهلة 10 دقائق.
- **المجدول:** داخل الخادم؛ يفحص كل دقيقة، يُنفّذ المتأخرة عند الإقلاع، يعيد المحاولة بعد 30 دقيقة من أي فشل، ويعلّم النسخ العالقة بعد إيقاف مفاجئ كفاشلة. `BACKUP_SCHEDULER=off` يعطّله.
- **API (للمالك فقط):** `GET /api/backups`، `PATCH /api/backups/settings`، `POST /api/backups/run`، `GET /api/backups/:id/download`، `DELETE /api/backups/:id`، وكلها مُدقَّقة. `GET /api/dashboard` يضيف `backup` للمالك.
- **الواجهة:** صفحة **النسخ الاحتياطي** (حالة، جدولة، سجل، تنزيل، حذف، شرح الاستعادة) وبطاقة حالة في الرئيسية مع زر «نسخ احتياطي الآن» وتحذير عند التقصير.
- **نسخة خارج الجهاز:** `BACKUP_COPY_DIR` ينسخ كل نسخة ناجحة إلى قرص خارجي/مجلد سحابي (فشله تحذير لا يُفشل النسخة). كذلك `BACKUP_DIR` و`BACKUP_MYSQLDUMP_PATH`.
- **الاستعادة:** `npm.cmd run db:restore -- <ملف> --yes` (`.sql` أو `.sql.gz`) مع **نسخة أمان تلقائية** قبلها.
- **الفحص:** `npm.cmd run test:backup` (16 فحصاً: الصلاحيات، التحقق، النسخ، سلامة الملف، التزامن، الحذف).

### 2) دليل الاستخدام داخل النظام (جديد)

- صفحة **دليل الاستخدام** (`/guide`) لكل المستخدمين: بحث نصي، أقسام قابلة للطي بخطوات وملاحظات، وأقسام المالك مخفية عن البائع.
- تحديث `USER_MANUAL.md`: فصل النسخ الاحتياطي والاستعادة أُعيد كتابته بالكامل، قسم التحديث من 0.2.x، وقواعد جديدة.

### 3) إصلاحات

| المشكلة | الإصلاح |
|---|---|
| خطأ «كلمة المرور الحالية غير صحيحة» كان يعيد 401 فتُخرج الواجهةُ المستخدمَ من النظام | يعيد `400`؛ والواجهة لا تعتبر انتهاء جلسة إلا عند `UNAUTHORIZED` |
| فتح جردين متزامنين ممكن | الفحص داخل معاملة بقراءة `FOR UPDATE` بعد قفل العدّاد؛ وتعديل سطر جرد يُقفل ويُعاد فحص حالته (لا تعديل أثناء الإغلاق) |
| سطر الجرد للصنف بكمية N يحمل وزن وقيمة وحدة واحدة | `expectedWeight` و`valueAtOpen` = وحدة × الكمية |
| إعادة تسمية مصنّع لا تنعكس على نص المصنّع في أصنافه | تحديث نص المصنّع في كل أصنافه داخل المعاملة |
| العيار يقبل `021` و`21.0` فيتكرر | صيغة موحّدة `^\d{1,2}$` وتخزين `String(k)` |
| العملة المحلية في الخادم من `LOCAL_CURRENCY` وفي الواجهة من الإعدادات | الخادم يستعمل `Setting.currency`؛ ورمز العملة 3 حروف لاتينية (يطابق عمود `VarChar(3)`) |
| `PATCH /items/:id` يتجاهل `addedAt`، ولا يرفض طقماً بكمية >1، ويمكنه التعديل بالتزامن مع بيع يُنهي الصنف | يحفظ `addedAt`، يرفض الكمية، ويقفل صف الصنف ويعيد فحص حالته |
| اقتراح سعر البيع يتجاهل `weightBasis` الخاص بالصنف | يُستعمل `item.weightBasis ?? أساس المحل` كما في تقييم الخادم |
| نموذج الصنف يحفظ أساس وزن المحل داخل كل صنف فيجمّده | لا يُرسل إلا تجاوز موجود أصلاً |
| البائع بلا إذن التكلفة يرى حقول الشراء ثم يُرفض حفظه | تُخفى بطاقة الشراء ولا تُرسل بياناتها |
| تعديل صنف عُطّل عياره يفشل في التحقق | عيارات الصنف المحفوظ تبقى متاحة |
| حقل «الكود» قابل للتعديل في شاشة التعديل لكن الخادم يتجاهله | يصبح للقراءة فقط مع توضيح |
| تقرير الفروقات يفشل للبائع (403) | البائع يرى ملخصاً محسوباً من أسطر الجرد |
| تقرير المبيعات بفلتر العيار يعدّ كل بنود الفاتورة | يُعدّ بند العيار المختار فقط |
| `/differences` لجرد غير موجود يعيد قائمة فارغة | `404` |
| طريقة الدفع تظهر «غير محددة» في كل الفواتير لأنها اختيارية وتبدأ فارغة | أصبحت إلزامية: الشاشة تختار الأولى تلقائياً، و`POST /sales` يرفض الطلب بلا `paymentMethodId` (422). الفواتير القديمة بلا طريقة تبقى كما هي |
| (اكتُشف أثناء الاختبار) نسختان احتياطيتان متزامنتان تتجاوزان فحص التشغيل | يُرفع علم التشغيل قبل أي `await` |

### 4) غير مصنَّف

- ما كان مُدرجاً قبل الإصدار تحت «غير مُصدَر» (التوضيحات والجوال والنسخ البسيط) أدناه.

## ما سبق إصدار 0.3.0 (كان غير مُصدَر بعد 0.2.1)

- **توضيح الأسعار:** أضيف نص موحّد `RAW_GOLD_PRICE_NOTE` في `apps/web/src/lib/copy.ts` يبيّن أن أسعار الذهب المعروضة هي **الخام قبل المصنعية**، وأن تكلفة القطعة تختلف حسب التصنيع والمصنع وبلد المنشأ والشحن. يظهر في صفحة الأسعار وبطاقة «أسعار الغرام اليوم» و`title` شرائح الهيدر.
- **واجهة الجوال:** طُيّت بطاقة «أين سعر البيع؟»، وأُخفيت الملاحظات التقنية والتوضيحية الطويلة والشروحات غير الجوهرية على الشاشات الصغيرة مع إبقاء كل الحقول والأزرار والتنبيهات المهمة.
- **نسخ احتياطي بسيط:** سكربت جديد `tools/backup-db.mjs` وأمر `npm.cmd run db:backup` ينشئ ملف SQL مؤرّخاً في `backups/` (مستثنى من git) دون إدخال كلمة مرور أو إيقاف MySQL.
- **التوثيق:** تحديث README وUSER_MANUAL وSYSTEM_SPECIFICATION وهذا سجل التغييرات، وإعادة توليد ملفَي PDF.

## 0.2.1 — 2026-11-18

إصدار **تثبيت وأمان** فوق 0.2.0: كل رسالة خطأ تصل للمستخدم أصبحت عربية، وتوليد أكواد الأصناف صار موثوقاً تحت التزامن، وحُصّنت الجلسات وحدود الطلبات، مع إصلاحات واجهة. **لا تغيير في مخطط قاعدة البيانات.**

### 1) معالجة الأخطاء — عربية بالكامل

| ما تغيّر | التفصيل |
|---|---|
| معالج مركزي جديد | `apps/api/src/middleware/error.ts` يعيد `{ error: { code, message, details?, requestId } }` برسالة عربية دائماً. |
| تحقق المدخلات | أخطاء Zod تُترجم إلى `422 VALIDATION_ERROR` مع مسار الحقل ورسالة عربية، وأول رسالة تظهر في `message`. |
| أخطاء قاعدة البيانات | رموز Prisma الشائعة تُطابق رسائل عربية مفهومة: تكرار (`P2002`)، عنصر غير موجود (`P2025`)، ارتباط (`P2003/P2014`)، حقل مطلوب (`P2011`)، قيمة طويلة (`P2000`)، تعذر اتصال/تهيئة (`P1001/P2021…`). |
| أخطاء التشغيل | JSON تالف → `400 INVALID_JSON`، جسم كبير → `413 PAYLOAD_TOO_LARGE`، أي خطأ غير متوقع → `500` برسالة عربية عامة. |
| رقم مرجعي | كل استجابة خطأ تحمل ترويسة `X-Request-Id` نفسه الظاهر في الرسالة، والتفاصيل الإنجليزية تُكتب في سجل الخادم فقط. |
| محرك التسعير | أخطاء `PricingError` تُعاد كما هي لأن رسائلها عربية أصلاً. |

### 2) أكواد الأصناف — مصدر واحد للحقيقة

- `GET /items/next-code` يحسب المعاينة من عدّاد `Sequence` وأعلى كود موجود فعلياً، فلا يعيد كوداً محجوزاً.
- في الوضع `AUTO` الخادم **يتجاهل أي كود يرسله العميل** ويولّد الكود داخل معاملة الحفظ؛ المعاينة في الشاشة للعرض فقط.
- في الوضع `MANUAL` الكود مطلوب، ورسالة التكرار عربية: «كود الصنف مستعمل مسبقاً…».
- عند تصادم نادر أثناء التزامن (`P2002`) تُعاد المحاولة تلقائياً بعد إعادة قراءة العدّاد.
- إصلاح خطأ «الكود مستخدم مسبقاً» عند إنشاء قطعتين متتاليتين من نفس الشاشة.

| حماية الحصة | الخطة المجانية في goldapi.dev = 100 طلب/ساعة؛ 10 دقائق = 6 طلبات/ساعة. لا يُنصح بفاصل أقل من 5 دقائق دون ترقية. |

### 2) توحيد تسمية واجهة الذهب

تم توحيد كل النصوص الظاهرة للمستخدم لتستعمل «ذهب» و«قطعة ذهب» في عنوان التطبيق ووصفه، والقائمة الجانبية، والرئيسية، وصفحة الأصناف، ونموذج القطعة، والمخزون، والإيصال، والإعدادات، ودخول النظام، وشاشة الجرد. أصبح الشعار النصي تحت اسم المحل «نظام تسعير ومخزون الذهب»، وزر الإضافة «إضافة قطعة ذهب».

> **لا تغيير في قاعدة البيانات:** أسماء الجداول والحقول والمسارات البرمجية بقيت كما هي، فلا حاجة لترحيل بيانات.

### 3) تصنيف «طقم» تلقائي

| ما تغيّر | التفصيل |
|---|---|
| بيانات أولية | `prisma/seed.ts` يضيف تصنيف **«طقم»** (id 19 عند التشغيل الحالي). |
| الواجهة | في `ItemForm.tsx`: اختيار النوع «طقم» يختار تصنيف «طقم» ويُعطّل حقل التصنيف، مع تلميح واضح. العودة إلى «قطعة» تُفرّغ التصنيف إن كان «طقم». |
| الخادم | `resolveCategoryId` في `routes/items.ts` يفرض تصنيف «طقم» النشط على أي صنف نوعه `SET`، حتى لو أرسل العميل تصنيفاً آخر. |
| الحماية | لا يمكن إنشاء طقم بتصنيف مضلّل أو بلا تصنيف إذا كان «طقم» موجوداً في القوائم. |

### 4) قائمة المصانع + إضافة سريعة للمورّد والمصنّع

| ما تغيّر | التفصيل |
|---|---|
| القوائم المرجعية | نوع جديد `MANUFACTURER` في `LookupKind`، مع تبويب **«المصانع»** في الإعدادات. |
| نموذج البيانات | `Item.manufacturerId` علاقة بـ`Lookup` (اسم العلاقة `ItemManufacturer`)، مع إبقاء `manufacturer` نصاً مرآة للتوافق. |
| API الأصناف | `manufacturerId` في مخطط Zod، `resolveManufacturer` يتحقق من النوع والتفعيل، ويُضمّن `manufacturerLookup` في استجابات القائمة/التفاصيل/البحث. |
| نموذج القطعة | المصنّع أصبح قائمة منسدلة بدل حقل نصي، والمورّد أيضاً مع زر **+**. |
| إضافة سريعة | مكوّن `LookupPicker` يضيف القيمة عبر `POST /lookups` ويختارها فوراً دون مغادرة الشاشة. |
| الصلاحيات | البائع يستطيع إضافة `SUPPLIER` و`MANUFACTURER` فقط؛ بقية الأنواع تبقى للمالك. |
| الحذف | المصنع المرتبط بقطعة يُعطَّل بدل حذفه (حذف ناعم)، حفاظاً على السجل. |

### 5) أساس الربح الثابت (`fixedBasis`)

- حقل جديد في الإعدادات وشاشة البيع يظهر عند اختيار «مبلغ ثابت»: **لكل غرام** (`GRAM`) أو **لكل قطعة** (`PIECE`)؛ الافتراضي `PIECE`.
- `GRAM`: يُضرب مبلغ الربح في `basisWeight` (وزن أساس الاحتساب الخام قبل التقريب).
- `PIECE`: يُضرب مبلغ الربح في `max(1, floor(pieceCount || 1))`.
- التقريب يُطبَّق بعد الضرب، مرة واحدة على السعر النهائي.
- الأطقم تمرّر إلى المحرك عدد المكوّنات ذات الوزن الأكبر من صفر؛ ف«100 لكل قطعة» على طقم من ثلاثة مكوّنات تعني 300، و«100 لكل غرام» تعني `100 ×` مجموع أوزان الأساس.
- القيمة تُحفظ مع الفاتورة في حقل `fixedBasis`، وتُعرض النتيجة التفصيلية في `profit.fixedBasis` و`profit.units`.
